# Ядро и система слотов

**Ядро (Core)** — это внутренняя трехмерная начинка сущностей Daicon (`DaiconEntity`), которая наделяет двумерные объекты трехмерными свойствами (физическими, положением в 3D-пространстве и тд.)

Ядро не отображается в сцене как обычный узел во время редактирования — оно формируется и управляется автоматически (существует в памяти абстрактно). При запуске игры или в режиме `@tool` в редакторе, ядро разворачивается с нуля на основе параметров инспектора и сохраненных данных слотов.

---

## Архитектура: 2D-оболочка и 3D-ядро

Любая сущность `DaiconEntity` (и её наследники: `KinematicDaicon`, `StaticDaicon`, `RigidDaicon`, `AnimatedDaicon`) устроена по принципу синхронизации:

1. **2D-нода (Оболочка):** Находится в дереве сцены 2D, отвечает за отрисовку спрайтов, анимаций, 2D-трансформ и экранный `z_index`.
2. **3D-нода (Ядро / `core`):** Автоматически создаётся как дочерний узел (`CharacterBody3D`, `RigidBody3D`, `StaticBody3D` или `AnimatableBody3D`). Управляет реальной физикой, коллизиями и перемещением в 3D-мире.

Позиция и трансформация между 2D и 3D синхронизируются автоматически через формулы проекции с учетом `tile_size` и `offset_3d`.

## Система слотов (DaiconSlots)

Чтобы добавить в 3D-ядро меши, формы коллизий, сенсоры или кастомные ноды, в Daicon используется **система слотов**.

Слот позволяет выбрать любой 3D-узел в редакторе, сериализовать его в `Dictionary` (сохраняя скрипт, свойства и метаданные), удалить временный узел из сцены и автоматически внедрить его внутрь скрытого 3D-ядра.

> [!INFO] Вкратце техническая реализация
> Вся информация узла записывается в специальный словарь `*_properties`. В дальнейшем этот словарь будет использоваться для динамического развертывания слотовых узлов в ядре.
> 
> ```mermaid

>     C -->|Восстановление| D(["🧩 DaiconSlots.expand_slot()"])
>     D -->|Внедрение в сцену| E(["🚀 3D-ядро core"])
> 
>     classDef purple fill:#f3e8ff,stroke:#9333ea,stroke-width:1.5px,color:#581c87;

### Стандартные слоты сущности

В инспекторе каждой `DaiconEntity` доступна группа **Slots**:

| Слот в инспекторе | Хранилище данных | Целевой родитель | Назначение |
| :--- | :--- | :--- | :--- |
| **Mesh Node** | `mesh_properties` | `core` | Отображение 3D-модели (`MeshInstance3D`) для отладки или визуала. |
| **Shape Node** | `shape_properties` | `core` | Основная коллизия тела (`CollisionShape3D` или `CollisionPolygon3D`). |
| **Whisker Node** | `whisker_properties` | `core` | Сенсор `Area3D` для расчета перекрытий и динамической сортировки `z_index`. |
| **Whisker Shape Node** | `whisker_shape_properties` | `whisker` | Форма коллизии для сенсора Whisker. Автоматически прикрепляется к `whisker_node`. |
| **Shader Cast Node** | `shader_cast_properties` | `core` | Луч `RayCast3D` для триггера эффектов шейдера при перекрытии препятствиями. |

## Как работают слоты на практике

Вам не нужно вручную настраивать сохранение — `DaiconSlots` делает всё автоматически:

* **Установка узла в слот:** Перетащите любой 3D-узел (например, `CollisionShape3D`) в поле слота инспектора. Узел будет упакован в данные, **удален из дерева 2D-сцены и внедрен внутрь `core`**.
* **Извлечение узла:** Нажмите на иконку сброса (или передайте `null`) — узел тут же распакуется обратно в сцену со всеми сохраненными настройками.
* **Защита от сбоев:** Если вы переименуете или удалите скрипт узла на диске, сцена не сломается и не сбросит значения — Daicon безопасно восстановит базовый класс и предупредит в консоли.
* **Сложные деревья:** Если узел содержит дочерние элементы, они упакуются и развернутся вместе с ним (включая скрипты, ресурсы и метаданные).

> [!TIP] Уникализация ресурсов
> При дублировании сущностей ресурсы слотов автоматически клонируются (`make_unique`), чтобы изменения на одном объекте не влияли на другие.

## Пользовательские слоты (`custom_slots`)

Помимо пяти стандартных слотов, `DaiconEntity` содержит массив:

```gdscript
@export_storage var custom_slots: Array[Dictionary] = []
```

Он предназначен для внедрения любых произвольных 3D-узлов и сложных деревьев нод внутрь ядра через код:

```gdscript
# Пример упаковки кастомного 3D узла в ядро сущности
var my_light = OmniLight3D.new()
var light_data = DaiconSlots.serialize_node(my_light, true)
entity.custom_slots.append(light_data)

# Разворачивание слота в ядре
DaiconSlots.expand_slot(light_data, entity.core)
```

## Прямой доступ к ядру через код

Для взаимодействия с ядром в коде используется переменная **`core`**.

```gdscript
# Пример доступа к CharacterBody3D внутри KinematicDaicon
var body := core as CharacterBody3D
if body:
    body.velocity = Vector3(1, 0, 0)
    body.move_and_slide()
    update_pos()
```

> [!DANGER]  Внимание при прямой модификации ядра
> Не удаляйте узел `core` вручную. При изменении позиций и скоростей всегда вызывайте `update_pos()`, чтобы 2D-оболочка синхронизировала свои экранные координаты с трехмерным положением ядра.
> 
> Будьте осторожны в своих админ-возможностях: имея неограниченный доступ к фундаменту, вы должны досконально понимать что делаете чтобы не повредить узел и его ядро.
