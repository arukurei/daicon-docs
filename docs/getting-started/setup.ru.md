# Настройка

## Дайкон-Ноды 

Каждая Daicon-нода представляет собой двухмерный узел с трехмерной начинкой. Таким образом, акцент разработки остается на привычном 2D-пространстве, пока за кулисами работает честная 3D-физика.

Начинка называется **ядром (core)**. Оно формируется автоматически и существует в памяти абстрактно. Для взаимодействия с ядром разработчику предоставляется удобная панель параметров в инспекторе. 

> [!NOTE] Прямой доступ 
> Если вам потребуется тонкий контроль над физикой, вы всегда можете обратиться к ядру напрямую через переменную `core` в коде и получить полный доступ ко всем свойствам 3D-тела.

## 1.Первые шаги

> ![daicon.png](../assets/images/nodes/daicon.png)
>  
> В первую очередь добавьте в вашу сцену корневой узел. Обычно в Godot это Node2D, но плагин предоставляет для этого специальный корневой узел **Daicon**.

> [!TIP] 
> Вы можете использовать обычные `Node2D` как корни сцены, если вам не требуется глобальная система сортировки и просвечивающих силуэтных шейдеров (подробнее в [[daicon.ru|Справочнике Daicon]]).

### Переопределение скрипта

К нодам плагина уже прикреплен базовый скрипт движка. Этот файл определяет функционал **всех** нод данного типа, поэтому его нельзя редактировать напрямую.

![Pasted image 20250222173306.png](../assets/images/pasted-images/Pasted%20image%2020250222173306.png)

Чтобы писать уникальную игровую логику для конкретного объекта, нужно расширить скрипт:

1. Нажмите правой кнопкой мыши по ноде в дереве сцены.
2. В контекстном меню выберите пункт **«Расширить скрипт»** (Extend Script).
3. В открывшемся окне поставьте галочку возле пункта **«Шаблон»** (Template).
4. Выберите готовый шаблон, предоставленный плагином.
5. Укажите путь сохранения в вашем проекте и нажмите **«Создать»**.

Теперь ваш `.gd` файл расширяет базовый класс, и вы можете безопасно писать собственную логику.

![Pasted image 20250222173449.png](../assets/images/pasted-images/Pasted%20image%2020250222173449.png)

> [!INFO]
> При установке Daicon предостовляет готовые скрипт-шаблоны в директории `addons/script_templates/`, обеспечивая вас чистым кодом для старта. Для подключения даных шаблонов, перенесите содержимое в папку `script_templates/` в корне проекта (по умолчанию `res/`)

## 2.Окружение

Для создания игрового мира плагин предлагает две ноды со схожим принципом работы:

### DaiconMap <small>(основная нода мира)</small>
> ![daicon-map.png](../assets/images/nodes/daicon_map.png)
> 
> Представляет собой многоуровневую карту тайлов. Каждый слой содержит уникальный **z-индекс**, являющийся показателем высоты данного уровня в пространстве. 
> 
> Другими словами, **z-сортировка** размещает объекты по модулируемой оси глубины на основе их индекса (ось **Y** в 3D).

### DaiconMapLayer <small>(автономный слой)</small>
> ![daicon_map_layer.png](../assets/images/nodes/daicon_map_layer.png)
> 
> Представляет собой единую независимую ноду `TileMapLayer` со встроенным собственным ядром `GridMap`.
> 
> Идеально подходит для съемных крыш, мостов, разрушаемых островков или отдельных декораций, требующих индивидуального шейдера.

---

### Настройка Окружения

![Pasted image 20250819122909.png](../assets/images/pasted-images/Pasted%20image%2020250819122909.png)

* **Mesh Library:** Библиотека 3D-мешей, из которых конструируется 3D-мир.
* **Physics Material:** Физические свойства поверхности тайлов (трение и упругость).
* **Z Step:** Шаг Z-индекса между этажами высоты.
* **Visible 3D:** Отображение 3D-сетки `GridMap` во вьюпорте.
* **Cell Size:** Размер одного трехмерного тайла в метрах (по умолчанию `1x1x1`).
* **Collision Layer и Mask:** Физические слои столкновений для 3D-мира.
* **Bake Navigation:** Запекание навигационной сетки для 3D.
* **Transform Rotation3D и Scale3D:** Поворот и масштаб трехмерного ядра.

> [!EXAMPLE] Авто-синхронизация координат
> Раздел **Transform Position3D** синхронизирован с **Position2D**. При перемещении Daicon-ноды в родном 2D-пространстве её трехмерное ядро автоматически меняет свою 3D-позицию.

#### Библиотека Меша

**DaiconMap** и **DaiconMapLayer** обязательно требуют библиотеку мешей (`MeshLibrary`) — это 3D-конструктор для тайлов (см. [[mesh.ru|Руководство по созданию MeshLibrary]]).

> [!TIP] Базовый Меш
> Вы можете воспользоваться базовым набором, который идет в стартовом комплекте Daicon.

Как только поле заполнено, в вашем `TileSet` появляется слой пользовательских данных **Item**. Он связывает 2D-тайл с соответствующим номером меша в библиотеке. При рисовании тайла на карте в 3D-пространстве автоматически строится привязанный блок.

![Pasted image 20250222153734.png](../assets/images/pasted-images/Pasted%20image%2020250222153734.png)

> [!WARNING] Важное правило для боковых стен
> Для тайлов вертикальных боковых стен (красные тайлы на примере) установите **локальный `z_index = -1`**. Это исключит визуальные ошибки сортировки, когда персонаж стоит вплотную между двумя стенами.
> 
> ![Pasted image 20250821114142.png](../assets/images/pasted-images/Pasted%20image%2020250821114142.png)

#### Создание слоев DaiconMap

1. Создайте несколько слоев в панели параметров `TileMap`.
2. Задайте им соответствующие Z-индексы с шагом `Z Step` (например, 0, 10, 20).
3. Перейдите в нижнюю панель «Карта тайлов».
4. Нажмите на меню инструментов в правом верхнем углу и выберите пункт **«Извлечь слои TileMap как отдельные узлы TileMapLayer»**.

Теперь ваши слои окружения представлены полноценными нодами `TileMapLayer`.

> [!TIP]
> Вам стоит тщательно следить за параметром `y-sort-enabled = true` и  `z_index & z_step` каждого дочерного слоя DaiconMap

С учетом 2.5D-проекции каждый слой выше 0 смещается вперед на один `z_step`, а каждый нижний - соответственно назад,  создавая тем самым наклонную Top-Down перспективу:

![Pasted image 20250222111927.png](../assets/images/pasted-images/Pasted%20image%2020250222111927.png)
> Если бы это было не так, перспектива была бы идеальным видом сверху (Top)

## 3.Игрок

> ![kinematic_daicon.png](../assets/images/nodes/kinematic_daicon.png)
> 
> Для кинематических обьектов используется нода **KinematicDaicon**. В ней собрано всё необходимое для создания динамических тел, коллизий и их автоматической 2.5D-сортировки.

### Создание игрока:

1. Добавьте в сцену узел **KinematicDaicon**.
2. Расширьте его скрипт через контекстное меню (**«Расширить скрипт»** → выберите шаблон `KinematicDaicon`).
3. Добавьте к персонажу визуал (например, `Sprite2D`, `AnimationPlayer` или `AnimationTree`).

---

### Настройка Игрока

![Pasted image 20250819124635.png](../assets/images/pasted-images/Pasted%20image%2020250819124635.png)

* **Tile Size:** Масштаб мира. Определяет, сколько экранных пикселей соответствуют 1 метру в 3D (по умолчанию 16)
* **Y 3D:** Позиция персонажа по вертикальной оси 3D-мира.
* **Z Step:** Шаг Z-индекса между уровнями высоты (должен совпадать со значением в `DaiconMap`)
* **Z Sort Coef:** Коэффициент высоты самого персонажа для правильного перекрытия других объектов.
* **Transform 3D:** Группа тонкой настройки 3D-ядра: смещение центра ног (`offset_3d`), вращение (`rotation_3d`) и масштаб (`scale_3d`)

---

### Система слотов (Slots)

В Daicon все трехмерные компоненты тела назначаются через **слоты**. Это позволяет собрать 3D-тело из обычных нод прямо в редакторе:

1. **Shape Node:** Слот для основной формы коллизии тела (`CollisionShape3D` или `CollisionPolygon3D`).
2. **Mesh Node:** Слот для 3D-модели (`MeshInstance3D`), используемой для визуала или дебага.
3. **Whisker Node & Whisker Shape Node:** Слоты для сенсора перекрытий `Area3D` и его формы.
4. **Shader Cast Node:** Слот для луча `RayCast3D`, определяющего препятствия перед персонажем.

> [!TIP] Как назначить узел в слот
> Создайте нужный 3D-узел (например, `CollisionShape3D`) в дереве сцены, выберите `KinematicDaicon` и укажите созданный узел в поле соответствующего слота в инспекторе. Узел автоматически сериализуется, исчезнет из 2D-дерева и внедрится внутрь скрытого 3D-ядра.

---

### Сенсоры: Whisker и ShaderCast

![Pasted image 20250819125046.png](../assets/images/pasted-images/Pasted%20image%2020250819125046.png)

В ядро персонажа встроены два ключевых инструмента пространственного взаимодействия:

* **Whisker (Сенсор перекрытий):** Представляет собой узел `Area3D`. Он отслеживает, когда персонаж заходит за стены или другие возвышенности, и динамически корректирует `z_index` персонажа, чтобы он корректно скрывался за преградой.
* **ShaderCast (Луч силуэтных шейдеров):** Представляет собой луч `RayCast3D`. Он стреляет вперед/в камеру и определяет, перекрыт ли персонаж стеной, передавая сигнал корневому узлу `Daicon` для прорезки силуэта.

![Pasted image 20250819134809.png](../assets/images/pasted-images/Pasted%20image%2020250819134809.png)
/// caption
- Зона сенсора **Whisker** (красная)
 - **ShaderCast** (Синий луч)

> [!INFO] Размеры и смещение Whisker
> * Для корректной работы форма коллизии для **Whisker Shape** должна быть чуть меньше габаритов персонажа (например, для куба 1x1x1 м форма вискера делается `0.9x0.9x0.9 м`). Это исключает ложные срабатывания на стыках тайлов.
> * По умолчанию Whisker сдвинут немного вперед (на 1.1 м), чтобы отслеживать именно препятствия перед персонажем.
